# v2.0.2 — Export / Import of alternative names + cache rebuild

## Goal

1. Let a user carry their custom labels to another browser / machine / profile
   (export to a file, import with either **merge** or **replace all**).
2. Give the user a **Rebuild local cache** button that discards the cached
   domains/display names and re-fetches them from Microsoft — without touching
   the custom labels.

**Export scope: `nameOverrides` only.** The domain cache (`domainCache`,
`displayNameCache`, `domainCacheExpiry`) is *derived* data — it re-fetches
itself from Microsoft's APIs on the target machine within seconds, is tied to
the signed-in partner account, and would bloat the file with real customer
domains. Exporting it buys nothing and leaks more. Only user-set overrides go
in the file — and the rebuild button (below) is the answer to a stale cache on
the target machine.

---

## Decision: the UI lives in a browser-action popup

Add `popup.html` + `popup.js` and register them as `action.default_popup`.

Why not buttons injected above the grid (the "obvious" option):

- The grid area is Shadow DOM that Partner Center mutates constantly; every
  injected control needs the same double-injection guards and observer
  bookkeeping as the column. More surface, more breakage.
- A file `<input>` / blob download inside a content script runs under the
  *page's* CSP. `partner.microsoft.com` can (and does) restrict `blob:`
  navigation. An extension page has the extension's own CSP — no such risk.
- Export/import is a rare, out-of-band action. Requiring the user to be on the
  GDAP page (signed in, tokens valid) to move a JSON file is pointless
  friction — the popup works on any tab.

**No new permissions.** Three things could have needed one, and none do:

- The popup is an extension page, so it reads/writes `chrome.storage.local`
  directly under the `storage` permission we already have.
- Download uses `URL.createObjectURL` + a synthetic `<a download>` click →
  no `downloads` permission.
- The rebuild button needs to find the GDAP tab and message it. `chrome.tabs.query({url})`
  and reading `tab.url` are allowed **without** the `tabs` permission when the
  extension holds a matching host permission — and we already have
  `https://partner.microsoft.com/*`. Do **not** add `"tabs"`; it would widen
  the store-listing permission warning for nothing.

## File format

`partner-center-alt-names-YYYY-MM-DD.json`

```json
{
  "type": "partner-center-alternative-names",
  "formatVersion": 1,
  "extensionVersion": "2.0.2",
  "exportedAt": "2026-08-06T09:14:22.115Z",
  "count": 3,
  "nameOverrides": {
    "a1b2c3d4-0001-4abc-8def-111122223333": "Acme — Demo tenant",
    "a1b2c3d4-0002-4abc-8def-111122224444": "Contoso (production)",
    "a1b2c3d4-0003-4abc-8def-111122225555": "Northwind — sandbox"
  }
}
```

- `type` + `formatVersion` are the import guard. Anything else → refuse with a
  clear message rather than silently importing garbage.
- `nameOverrides` is byte-for-byte the shape already in `chrome.storage.local`,
  so export is a read and import is a write — no mapping layer.
- Everything outside `nameOverrides` is informational; the importer ignores
  unknown keys so future versions can add fields without breaking v1 readers.

### 2. `popup.html` (new)

Small, self-contained, no dependencies — matching repo style. Three sections,
in this order:

**Alternative names**
- Status line: `N alternative name(s) stored`.
- **Export…** button → downloads the JSON.
- **Import — merge** button — imported entries win per tenant; anything not in
  the file is left alone. The "add a colleague's labels to mine" path.
- **Import — replace all** button — wipes `nameOverrides` first, so storage
  ends up exactly matching the file. The "clean move to a new browser" path.
- Both import buttons share one hidden
  `<input type="file" accept="application/json,.json">`; the click handler
  records the mode, then opens the picker.
- Replace-all asks for confirmation **only when overrides already exist**, and
  the prompt names the number about to be discarded ("Replace all 12 stored
  name(s) with the contents of this file?"). Use `window.confirm` — it's
  allowed on an extension page and this is exactly the one destructive action
  in the popup.

**Local cache**
- Status line: `N domain(s) / M display name(s) cached · expires <date>`, or
  `No cached data` when the keys are missing/expired.
- **Rebuild local cache** button (see §3 for behaviour).
- Caption under it: *Custom names are never affected.* Say it in the UI, not
  just the code — this is the button people will be afraid to press.

**Shared**
- One status `<div>` for success/error text (green/red), no `alert()` for
  outcomes.
- Styling in an inline `<style>` block. MV3's default CSP restricts
  `script-src`, not `style-src`, so a `<style>` element is fine — but **no
  inline `onclick` handlers**; all listeners are attached from `popup.js`.

### 3. `popup.js` (new)

```
OVERRIDE_KEY   = 'nameOverrides'
CACHE_KEY      = 'domainCache'
DISPLAYNAME_KEY = 'displayNameCache'
EXPIRY_KEY     = 'domainCacheExpiry'
GDAP_URL_GLOB  = 'https://partner.microsoft.com/dashboard/v2/customers/granularadminaccess/*'
FORMAT_TYPE    = 'partner-center-alternative-names'
FORMAT_VER     = 1
MAX_FILE_BYTES = 1_048_576   // 1 MB — a 5k-entry file is ~250 KB
MAX_ENTRIES    = 5000
MAX_NAME_LEN   = 200
```

These four storage keys are duplicated from `content.js`. There is no module
system here and no build step, so that's the cost of a second page — keep the
names identical and note in both files that they must stay in sync.

- `refreshStatus()` — read all four keys in one `chrome.storage.local.get`,
  render the override count and the cache line. Called on open and after every
  action, so the popup never shows stale counts.
- `doExport()` — read storage, build the envelope, `new Blob([json], {type:'application/json'})`,
  `URL.createObjectURL`, click a temp `<a download="partner-center-alt-names-<date>.json">`,
  then `URL.revokeObjectURL` on a `setTimeout(…, 1000)`. Exporting zero
  overrides is refused with "Nothing to export" rather than writing an empty file.
- `doImport(file, mode)` where `mode` is `'merge'` or `'replace'` — validate
  hard, in this order, failing loudly at each step:
  1. `file.size <= MAX_FILE_BYTES`.
  2. `JSON.parse` succeeds and yields a plain object.
  3. `type === FORMAT_TYPE` and `formatVersion === FORMAT_VER`.
  4. `nameOverrides` is a plain object with `<= MAX_ENTRIES` keys.
  5. Per entry: key matches `UUID_RE` (same regex as `content.js`) → lowercase
     it; value is a string, `.trim()`-ed, non-empty, `<= MAX_NAME_LEN` chars.
     Entries that fail are **skipped and counted**, not fatal — one bad row
     shouldn't kill a 200-name import.
  6. Write, mode-dependent:
     - `merge` → `chrome.storage.local.set({ [OVERRIDE_KEY]: {...existing, ...clean} })`
     - `replace` → `chrome.storage.local.set({ [OVERRIDE_KEY]: clean })`

     Note `replace` is a `set` of the whole key, not a `remove` + `set` — one
     atomic write, one `onChanged` event, no window where the user has nothing.
     A **valid file with zero usable entries** must not be allowed to silently
     wipe everything in replace mode: if `clean` is empty, refuse and say so.
- Report the outcome precisely, and differently per mode:
  - merge → `Imported 12 name(s) — 9 new, 3 updated, 1 skipped (invalid)`
  - replace → `Replaced all names — 12 stored, 1 skipped (invalid) (7 removed)`
- Reset `input.value = ''` after handling so re-picking the same file re-fires
  `change`.

- `doRebuild()` — the cache rebuild. Order matters:
  1. `chrome.storage.local.remove([CACHE_KEY, DISPLAYNAME_KEY, EXPIRY_KEY])`.
     **Never** include `OVERRIDE_KEY` in that array — write it as a named
     constant list with a comment, because a careless edit here silently
     destroys the user's labels.
  2. `chrome.tabs.query({ url: GDAP_URL_GLOB })` to find an open GDAP tab.
  3. If one exists → `chrome.tabs.sendMessage(tab.id, { type: 'ALTNAME_REBUILD_CACHE' })`
     and await the reply. The content script has the page's `sessionStorage`
     tokens; the popup does not, so the refetch **must** happen there. Report
     `Cache rebuilt — 148 domain(s), 152 name(s).`
  4. If the tab exists but doesn't answer (extension reloaded since the page
     loaded, so the old content script is orphaned — `chrome.runtime.lastError`
     is set), report: `Cache cleared. Refresh the Partner Center tab to rebuild it.`
     Check `lastError` explicitly; an unanswered `sendMessage` otherwise fails
     silently with an `undefined` response.
  5. If no GDAP tab is open, report the same "cleared, open the page to
     rebuild" message. Clearing alone is already a valid outcome — `content.js`
     rebuilds on its next load. The tab message is an optimisation, not the
     mechanism.
  6. If the content script replies that the refetch failed (expired tokens),
     report: `Cache cleared, but the refetch failed — sign in again on the
     Partner Center page and refresh.`
  7. `refreshStatus()` at the end regardless.

### 4. `content.js`

Three additions plus one small refactor.

- **Live refresh on import.** Today `overrideMap` is only loaded at `init()`,
  so an import while the GDAP tab is open does nothing until F5. Add:

```js
chrome.storage.onChanged.addListener((changes, area) => {
  if (area !== 'local' || !changes[OVERRIDE_KEY]) return;
  overrideMap = new Map(Object.entries(changes[OVERRIDE_KEY].newValue || {}));
  dbg('Overrides changed externally:', overrideMap.size, 'entry(ies).');
  publishAltIndex();
  const g = findGrid(document);
  if (g && g.shadowRoot) injectColumn(g.shadowRoot);
});
```

  Note the existing `persistOverrides()` write fires this too — that's a
  harmless self-echo (the map is rebuilt to the value it already holds, and
  `renderCell`'s `data-rendered` signature check makes the re-render a no-op).
  Not worth a suppression flag.

- **Refactor `refetch()` into a reusable `rebuildCache()`.** The debug helper
  at [content.js:768](../content.js#L768) already does exactly what the popup
  needs: `Promise.all([fetchAllDomains(), fetchDisplayNames()])`, rewrite the
  maps, `writeCache()`, `loadState = 'ready'`, `publishAltIndex()`, re-inject.
  Lift that body into a named `async function rebuildCache()` returning
  `{ ok, domains, names }`, and have both the debug helper and the new message
  handler call it. No behaviour change — one implementation, two callers.

  One correction to the existing logic while moving it: `refetch()` treats a
  partial result as success (`if (fresh || names)`). For the popup's report to
  be honest, `rebuildCache()` should return `ok: !!(fresh || names)` and the
  actual counts, so a GDAP-only failure surfaces as `148 domain(s), 0 name(s)`
  rather than a clean "rebuilt".

- **Message handler for the popup:**

```js
chrome.runtime.onMessage.addListener((msg, sender, sendResponse) => {
  if (!msg || msg.type !== 'ALTNAME_REBUILD_CACHE') return; // not ours
  rebuildCache().then((r) => sendResponse(r))
                .catch((e) => sendResponse({ ok: false, error: String(e) }));
  return true; // keep the message channel open for the async reply
});
```

  The `return true` is load-bearing — without it the channel closes before
  `rebuildCache()` resolves and the popup sees `undefined`. Equally important
  is the early `return` (not `return true`) for messages that aren't ours, so
  we don't hold channels open for other senders' traffic.

  The handler does **not** clear storage — the popup already did that before
  messaging. It just refetches and writes fresh values. Keep it that way: one
  owner per action.

- **Debug helpers** on `window._tenantDomainDebug`: `exportOverrides()`
  returning the envelope object, `importOverrides(obj, mode)` reusing the same
  validation, and `rebuildCache()` (now that it's a named function, just expose
  it). This keeps the whole 2.0.2 surface testable from DevTools without the
  popup.

  On the duplicated validator: keep it in `popup.js` and let the `content.js`
  debug version be thinner (no file-size check, since there's no file). The
  alternative is a shared module, and this repo has no build step and no
  module loading in content scripts — not worth it for ~15 lines.

## Edge cases / notes

- **Overrides for tenants that don't exist in the target account** are kept in
  storage but never rendered (no matching row). Harmless, and correct — the
  user may switch accounts back. Don't try to prune against the customer list.
- **Tenant ID casing**: storage is lowercase by convention; the importer
  lowercases on the way in, so a hand-edited file with uppercase GUIDs still
  works.
- **Empty-string values** are treated as "no override" everywhere in
  `content.js`, so the importer drops them rather than storing dead keys.
- **Rebuild never touches `nameOverrides`** — this is the single most important
  invariant in the release. It is enforced in one place (the key list passed to
  `chrome.storage.local.remove`) and stated in the UI.
- **Rebuild with an expired session** clears the cache and fails the refetch,
  which briefly leaves the column showing `—`/`Unknown` for uncached tenants.
  That's recoverable (sign in, refresh) and honest, but the popup must say so
  rather than reporting success — hence the explicit `ok:false` path.
- **Two GDAP tabs open**: message the first match only. The second tab's
  `chrome.storage.onChanged` listener picks up the new cache anyway once the
  first finishes writing... except that listener only rebuilds `overrideMap`.
  Leave it — a second tab showing slightly stale domains until refresh is not
  worth widening the listener. Note it, don't fix it.
- **`.plan/` and any test file must use fictional data only** (Acme, Contoso,
  Northwind, `a1b2c3d4-…` GUIDs) — this repo is public.

## Test plan

Load unpacked, reload the extension, then:

1. Set 3 custom names on the GDAP page → popup shows `3 alternative name(s) stored`.
2. Export → file downloads, opens as valid JSON with 3 entries and the correct envelope.
3. `clearOverrides()` from DevTools → popup shows 0 → **Import — merge** →
   popup shows 3, and the open GDAP tab updates the column **without a refresh**.
4. Search one of the imported custom names in Partner Center's search box →
   the row comes back (confirms `publishAltIndex()` ran after import).
5. **Merge semantics**: set a 4th name by hand, then merge a file whose 3
   entries include a different label for one of them → result is 4 stored, the
   collision took the file's value, the hand-set 4th survived.
6. **Replace semantics**: from that state, **Import — replace all** with a
   2-entry file → confirmation prompt names the 4 about to go; after OK,
   exactly 2 remain and the grid drops the removed labels live.
7. Negative imports — each gives a specific red message and leaves storage
   untouched: a random `.json`, a `.txt` renamed to `.json`, `formatVersion: 99`,
   an empty `nameOverrides: {}` in **replace** mode (must refuse, not wipe).
   A file with one bogus tenant-ID key is the exception: it imports the valid
   rows and reports the skip count.
8. Export with 0 overrides → "Nothing to export", no file written.

Cache rebuild:

9. Note the cache line in the popup, then **Rebuild local cache** with the GDAP
   tab open and signed in → status reports non-zero domain and name counts, the
   cache line shows a fresh 30-day expiry, and the grid repopulates without a
   refresh.
10. **The invariant**: with 3 custom names stored, rebuild → still 3, still
    displayed, still searchable. Run this every time the rebuild code is
    touched.
11. Rebuild with **no** Partner Center tab open → "Cache cleared. Refresh the
    Partner Center tab to rebuild it."; `chrome.storage.local.get` shows the
    three cache keys gone and `nameOverrides` intact. Then open the GDAP page →
    it refetches on load.
12. Rebuild against an **orphaned** content script (reload the extension at
    `chrome://extensions`, don't refresh the page, then rebuild) → the same
    "refresh the tab" message, not a silent success and not an unhandled error.
13. Rebuild with an **expired session** (leave the tab idle until the tokens
    lapse, or clear `AuthContextData` / `CustomerSvcAdminKey` from
    `sessionStorage`) → reports the refetch failure explicitly; overrides
    still intact.
14. `./build.ps1` → zip contains `popup.html` and `popup.js`; load the unpacked
    zip contents fresh and repeat steps 2 and 9.
