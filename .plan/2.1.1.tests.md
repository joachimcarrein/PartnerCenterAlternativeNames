# 2.1.1 — first tests: import safety and the OData filter rewriter

**Status: implemented, all 42 assertions passing, and mutation-verified.**
**No version bump: the shipped extension is byte-for-byte unchanged.** Nothing
under `tests/` is loaded by Chrome or packed by `build.ps1` (verified — see
[Shipping](#shipping)). This document sits alongside `.plan/2.1.1.md` rather
than claiming a version of its own.

## Why these two, and not a suite

Tests were scoped deliberately, on the basis of what the 2.1.1 bugs actually
showed:

- The `{}` cache poisoning was **exactly** the kind of bug a unit test catches:
  pure logic over plain objects.
- The GDAP token moving was **not**. It was an external contract change by
  Microsoft. No unit test, and no integration test runnable without live
  credentials against a Microsoft portal, would ever have detected it.

So tests here are bought to protect *our own* logic from drifting — not as
insurance against another 2.1.1. Two surfaces earned them, ranked on
consequence × testability.

### 1. `popup.js` — the import path (19 assertions)

`nameOverrides` is the one storage key with **no server-side source of truth**
(CLAUDE.md, Storage keys). Everything else re-fetches from Microsoft in
seconds; custom names exist only in the user's browser. A bug here loses data
permanently, and the user would have no reason to have kept a backup.

`validateEnvelope()` was already a clean pure function (object in,
`{clean, skipped}` out, typed throws), so it needed no refactoring at all.
`doImport()` needed stubs, but it is where the actual data-destruction guard
lives, so it is covered too:

- Envelope gating: non-objects, foreign `type`, unsupported/missing
  `formatVersion`, missing or non-object `nameOverrides`, over the entry cap.
- Per-entry validation: id lowercasing, value trimming, and the four skip
  reasons (non-UUID key, non-string value, blank after trim, over the length
  cap) each skipping the row without failing the whole import. Boundary case: a
  name exactly at `MAX_NAME_LEN` is accepted.
- **The wipe guard**: a structurally valid file whose entries are all unusable
  is refused in replace mode, existing names survive untouched, and
  `chrome.storage.local.set` is not called *at all*.
- Write semantics: replace makes storage match the file exactly; merge lets
  imported entries win per tenant and leaves other tenants alone.
- **A single `set()`, never `remove()` + `set()`** — asserted for both modes,
  because the file contract requires that there be no window where the data is
  briefly empty.
- Malformed input: over the byte cap (rejected before the file is even read),
  invalid JSON, a reader failure, and an envelope error reaching the user
  verbatim. None of them write.

### 2. `search-inject.js` — the OData `$filter` rewriter (23 assertions)

Fiddly string surgery where **every limit is load-bearing** (constraint 6, all
found the hard way), and where failure is silent: a customer quietly stops
being findable, or the search breaks with a red banner.

- The bridge: an `INDEX` message is what makes matching possible at all; a
  message from a foreign `source` is ignored; `REQUEST_INDEX` is posted on load
  because `content.js` may have published before this script existed.
- `extractQuery()`: pulls the query out of the `contains(tolower(displayName),
  tolower('…'))` clause, and **un-doubles OData's escaped single quotes**
  (`o''brien` on the wire means `o'brien`).
- `matchingTenantIds()`: substring, case-insensitive, whitespace-trimmed; an
  empty query matches nothing.
- When it must decline: other hosts, non-string input, no query string, no
  `$filter`, a filter with no `displayName` (not our call), no index, and no
  matches.
- **The node limit**, both sides of the boundary: exactly `MAX_CLAUSES` matches
  still expand and produce exactly that many clauses; **past** the cap
  expansion is skipped entirely, degrading to normal results rather than a
  filter the API rejects.
- The rewritten filter: **one flat OR group** (asserted structurally — the base
  filter's own parens are stripped, `((` never appears, and the only outer
  parens are at the very edges), original `displayName` clauses intact, every
  other query parameter byte-identical, the new `$filter` re-encoded with
  spaces as `%20` and never `+`, and an apostrophe in the query surviving the
  round trip.
- Wiring: `XMLHttpRequest.open` actually receives the rewritten URL, and a
  non-search XHR passes through untouched.

## How the tests reach IIFE code without changing it

Every runtime file is a bare `(() => { ... })()` with nothing exported —
deliberate, since the source files *are* the shipped files and there is no
module system. Three options were considered:

| Option | Verdict |
|---|---|
| Regex out individual functions and `eval` them | Rejected. What I used for the throwaway 2.1.1 cache check. Breaks on any reformat, no line numbers on failure. |
| Add `module.exports` footers to the shipped files | Rejected. It modifies shipped code, and `search-inject.js` runs in the page's MAIN world where a stray global `module` from the page's own bundler could make the footer do something unintended. |
| **Strip the IIFE wrapper and run the body in a `node:vm` context** | **Chosen.** Zero changes to shipped code, zero dependencies. |

`tests/helpers/load-iife.js` implements the third. Two language facts make it
work:

- Top-level `function` declarations in a **Script** become properties of the
  context's global object even under `'use strict'` (strict mode only changes
  this for *block*-level declarations). So the functions come back out on their
  own.
- Top-level `const`/`let` do **not** — they stay lexical. The functions close
  over them fine, but to read a constant (`MAX_CLAUSES`, `MAX_ENTRIES`, …) a
  test passes an `expose` snippet, which is appended to the same source string
  and therefore shares that scope.

Two traps worth recording:

- **Only host globals may be injected.** A fresh vm context already owns every
  ECMAScript intrinsic in its own realm; injecting the outer realm's `Object`,
  `Array`, … on top mixes realms and makes `instanceof` unreliable inside the
  module. The first draft did this and had to be corrected.
- **Cross-realm objects break `deepStrictEqual`.** Values built inside the vm
  carry that realm's `Object.prototype`, so the assertion reports "same
  structure but not reference-equal". `stubs.js` exports `plain()` — a JSON
  round-trip — to compare by value.

The only coupling to source formatting is the wrapper's first and last line,
which is far more stable than per-function extraction. If that ever becomes a
burden, the fallback is a `typeof module !== 'undefined' && typeof window ===
'undefined'` footer per file.

## Verification: the tests were mutation-tested

Both suites passed on the first run, which for logic this fiddly is a reason
for suspicion, not confidence. Four mutations were introduced into the real
sources and each had to be caught:

| Mutation | Result |
|---|---|
| `MAX_CLAUSES` 4 → 99 (node-limit guard defeated) | 2 failures |
| Stop stripping the base filter's outer parens (nested OR group) | 1 failure |
| Drop the OData `''` → `'` unescaping | 2 failures |
| Remove the `replace` + zero-usable-entries wipe guard from `popup.js` | 1 failure |

Both files were then confirmed byte-identical to their pre-mutation state
(`cmp`) and re-checked with `node --check`.

## Running them

```powershell
node --test "tests/**/*.test.js"          # 42 assertions, ~0.1s
node --test tests/popup-import.test.js    # one suite
```

**Quote the glob, and do not pass the directory.** `node --test tests` fails
with a `MODULE_NOT_FOUND` error for the directory itself — the runner tries to resolve the
directory as an entry point rather than discovering test files in it. The
quoted glob is expanded by Node itself, not the shell, so the exact same
command works in both PowerShell and bash (verified in both).

The `*.test.js` suffix is also what keeps `tests/helpers/` out of the run:
Node treats *every* file under a directory named `tests` as a test file when it
does discover them, so helpers must not be swept in by pattern.

No `package.json`, no `node_modules`, no config: `node:test` and `node:assert`
are built into Node, so the repo's no-dependencies rule is intact.

## Shipping

Nothing under `tests/` ships. `build.ps1` packs from an **explicit allowlist**,
so a new directory is excluded by default rather than needing to be
blacklisted. Verified by building and listing the archive — 9 entries,
`tests/` absent:

```
docs/icons/icon{16,48,128}.png
background.js  content.js  manifest.json  popup.html  popup.js  search-inject.js
```

`build.ps1`'s comments were updated to name `tests` among the excluded paths.
Documentation only — the allowlist logic needed no change.

## Not covered, and why

- **Shadow DOM traversal, column injection, the MutationObserver.** Would need
  jsdom (a dependency), and its shadow-root/slot fidelity would not match
  Partner Center's real markup — so the tests would be exercising the fixture,
  not reality. The genuine risk there is Microsoft changing markup, which a
  fixture-based test cannot see either. Same trap as the 2.1.1 token bug.
- **Anything hitting the Microsoft APIs.**
- **`content.js` cache semantics.** Already covered by assertions during
  2.1.1 itself, but as a throwaway harness rather than a committed suite. This
  is the obvious next candidate, and `load-iife.js` now makes it cheap —
  `content.js` needs a larger stub set (`document`, `sessionStorage`,
  `crypto`, `chrome.runtime`), which is the only reason it was not folded in
  here.
- **`findNameButtonClick()` and the Shift-invert truth table.** `.plan/2.1.0.md`
  already works all four cells by hand; encoding them needs only a fake
  `composedPath` of plain objects. Cheap, and worth doing next.

## The higher-priority robustness work is still not a test

2.1.1 degraded 7 of every 10 rows while reporting success, because 71 healthy
domains were enough to set `loadState = 'ready'`. No test catches that class of
failure — a **health signal** does: surfacing "display names: 0 of 71" in the
popup, or distinguishing "lookup failed" from "this customer has no name" in
the cell. That remains the single highest-value robustness change outstanding.
